# 전파 감지기 (Android, Kotlin)

폰 주변의 **블루투스(BLE) · 와이파이 · 기지국** 전파를 페어링 없이 그냥 읽어서,
**평소에 없던 새 신호가 나타나면 제조사·기기 종류·대략 거리로 알려주는** 앱입니다.

- 설치형 앱이라 브라우저처럼 `chrome://flags`를 켜거나 기기 선택(페어링) 창을 거칠 필요가 없습니다.
- 읽은 신호는 폰 밖으로 보내지 않습니다. 인터넷 권한 자체를 쓰지 않습니다.
- 기준 저장(`기준 저장`)을 한 번 눌러 두면, 그다음부터 **처음 잡히는 신호**와 **세기가 확 오른 신호**만 따로 표시합니다.

이 폴더는 **앱 두 개**를 만듭니다. 하나는 원래의 `전파 감지기`(`com.jihun.signalradar`),
다른 하나는 `전파 감지기 (내 주변)`(`com.jihun.signalradar.nearby`)입니다. 패키지가 달라서
**지웠다 다시 깔 필요 없이 나란히 설치**됩니다.

## 전파 감지기 v1.5 · 내 주변 앱 v1.3 (2026-11-19)

### `🔍 기기 이름 더 읽어오기` 한도를 3.5초로 (두 앱 공통, `common/`)

- 지훈 님 요청(`1.5초 너무 짧아` → `3.5초로 해줘`)으로 전체 한도를 **`TIMEOUT_MS = 3_500`(3.5초)**,
  서비스 발견 뒤 이름 읽기 단계는 **`READ_TIMEOUT_MS = 2_000`(2.0초)** 으로 늘렸습니다.
- 1.5초는 연결+서비스 발견+읽기를 다 합친 시간이라, 느린 이어폰·워치는 방송에 이름이 있는데도
  끝나기 전에 끊겨 `응답이 없었어요`로 보였습니다. 3.5초는 그 응답까지 기다립니다.
- 진행 문구는 `GATT 연결 중… (최대 3.5초)`, 실패 문구는 `3.5초 동안 응답이 없었어요. …`.
  거절(133·257)·끊김은 예전처럼 기다리지 않고 바로 끝내고, **UI 먼저 → `gatt-close` 백그라운드 정리**,
  **`Device Name(0x2A00)` 한 개만 읽기**, **`+12 dBm` 거리 보정**은 그대로입니다.

## 전파 감지기 v1.4 · 내 주변 앱 v1.2 (2026-11-19)

### `🔍 기기 이름 더 읽어오기` — 1.5초 안에 끝남 (두 앱 공통, `common/`)

- **`Device Name(0x2A00)` 한 개만** 읽습니다. `Manufacturer Name(0x2A29)` 두 번째 왕복을 없애
  진행 문구도 `기기 이름 읽는 중…` 하나로 줄었습니다(제조사는 이미 OUI·Bluetooth SIG 표로 알고 있음).
- **UI가 먼저, GATT 정리는 그다음**: `finish()`가 `onResult`를 `Handler.post`로 메인 스레드에 먼저 넘기고,
  `disconnect()`·`close()`는 별도 백그라운드 스레드(`gatt-close`)에서 실행합니다. BLE 스택의 동기 락을
  UI 스레드에서 기다리지 않으므로 버튼이 멈춘 것처럼 보이지 않습니다. `onStatus`도 항상 `Handler.post`로
  메인 스레드에서만 호출됩니다.
- **타임아웃 2단**: 전체 `TIMEOUT_MS = 1_500`(1.5초), 서비스 발견 뒤 이름 읽기 단계에는
  `READ_TIMEOUT_MS = 800`(0.8초)을 따로 걸어, 연결만 받고 읽기에는 답하지 않는 애플 기기·최신 폰에서도
  0.8초 만에 결과를 띄웁니다. 실패 문구는 `1.5초 동안 응답이 없었어요. …` / `이름을 읽는 데 응답이 없었어요. …`.

### `+12 dBm` 송신 출력을 1m 기준 세기로 오해하던 거리 계산 수정 (`identify/Classifier.kt`)

- 애플 기기는 광고 패킷의 txPower 자리에 **안테나 출력(+12 dBm)** 을 넣습니다. 이걸 "1m에서의 세기"로
  쓰면 `-50 dBm`짜리 기기가 `60m+`로 계산됩니다.
- 1m 기준 세기로 쓰는 값은 **`-100..-20 dBm`** 으로 제한했고(`Classifier.isOneMetreTxPower`), 그 밖의 값이면
  기본값 `-59 dBm`을 씁니다. 상세 카드도 그런 값을 `광고된 송신 출력: +12 dBm (1m 기준 세기가 아니라
  거리 계산에는 쓰지 않아요)` 로 표시합니다.

## 내 주변 앱 v1.1 · 전파 감지기 v1.3 (2026-11-19)

### 레이더 전체화면 (`전파 감지기 (내 주변)` v1.1)

- `내 주변` 레이더 카드 오른쪽 위의 **`⛶ 전체화면`** 버튼을 누르면 상단 헤더(앱 이름·상태 배지),
  범례·안내 문구·`10m 이내 기기` 목록, 하단 탭 바가 모두 사라지고 상태바·내비게이션바까지 숨습니다
  (`WindowInsetsControllerCompat.hide(Type.systemBars())`, 복귀 시 `show`).
- 사라지지 않고 남는 것은 **`내 10m 안 기기 N개` + `▶ 스캔 시작/■ 스캔 중지` 한 줄**, **`폰이 보는 방향: …`**,
  그리고 카드 오른쪽 위가 **`✕ 축소`** 로 바뀐 같은 버튼입니다. 레이더 카드는 화면 너비에 맞춘 **정사각형**이
  되어 가운데 놓이고, 좌우 여백을 18dp → 10dp로 줄여 원이 최대한 커집니다.
- **뒤로가기**: `OnBackPressedCallback`이 전체화면일 때만 켜져 있어, 뒤로가기는 앱을 닫지 않고
  전체화면만 해제합니다. 한 번 더 누르면 평소처럼 앱이 닫힙니다. `거리` 탭으로 옮겨가도 자동으로 해제됩니다.

### `🔍 기기 이름 더 읽어오기`가 빨라짐 (두 앱 공통, `common/`)

- GATT 한도가 **8초 → 2.5초**로 줄었습니다(`GattNameReader.TIMEOUT_MS = 2_500`).
- `onConnectionStateChange`에서 **실패 상태(133·257 등)이거나 기기가 끊으면** 타임아웃을 기다리지 않고
  바로 `disconnect()` + `close()` 후 결과를 돌려줍니다(`GattNameReader.shouldStop`). 거절 응답을 받고도
  8초를 기다리던 동작을 없앴습니다.
- `connectGatt(..., TRANSPORT_LE)` → `discoverServices()` 성공 시 `Device Name(0x2A00)`을 먼저 읽고,
  이어 `Manufacturer Name(0x2A29)`를 읽습니다. 특성이 없거나 읽기 요청이 거부되면 그 자리에서 다음 단계로
  넘어가거나 끝냅니다. 버튼 문구는 `🔍 이름 읽는 중…` 으로 짧게 유지합니다.

## 내 주변 앱 v1.0 (2026-11-19)

같은 전파 읽기 기능에 **10m 반경 원형 레이더**를 더한 별도 APK입니다.

- **하단 탭 `📏 거리` / `📡 내 주변`**: 예전 화면 아래 빈 공간에 있던 안내 문구 자리를 없애고,
  두 버튼을 하단 탭 바(높이 62dp, 선택된 탭은 청록색 + 밑줄)로 바꿨습니다. 누를 때마다 화면이 전환됩니다.
  `📏 거리` 탭은 v1.2 화면(요약·`스캔 시작`·`기준 저장`·필터 칩·신호 목록·상세 창·`🧭 방향 찾기`·
  `🔍 기기 이름 더 읽어오기`)을 그대로 씁니다.
- **10m 원형 레이더**: 중심이 `나 (0m)`이고 `2m`·`5m`·`10m` 동심원 눈금이 있습니다. 추정 거리가
  **10.5m 이하**인 블루투스·와이파이만 점으로 찍고(기지국은 거리를 알 수 없어 제외),
  중심에서의 반지름은 `거리 ÷ 10m` 비율입니다. 20dp보다 가까운 기기는 `나` 표시를 가리지 않도록
  20dp 위치에 그립니다.
- **종류 구분**: 블루투스는 **파랑(#38BDF8)**, 와이파이는 **초록(#34D399)** 점입니다. 점 옆 라벨은
  `이름` + `추정 종류 · 거리`(예: `에어팟 · 0.6m`, `공유기 · 4.1m`) 두 줄이고, 종류는
  `identify/DeviceType.kt`가 `Signal.kind`를 에어팟·버즈·공유기·핫스팟·추적기·워치·스마트폰 등으로 줄인 값입니다.
  레이더 아래 범례에 `● 블루투스 ● 와이파이`, `◉ 방향 측정됨 ◌ 방향 미측정`이 있습니다.
- **방향**: `Compass` 센서와 연결되어 폰을 돌리면 레이더 판이 함께 돌아갑니다(화면 위쪽 = 폰이 보는 쪽,
  북/동/남/서 글자는 항상 똑바로). 상단에 `폰이 보는 방향: 북동쪽 12°`처럼 현재 방위각이 나옵니다.
  기기별로 `🧭 방향 찾기`로 피크 방위가 측정되면 `SignalRepository`에 그 방위가 저장되고, 레이더는 그 기기를
  **실제 측정 방위에 진한 점 + 중심에서 뻗는 선**으로 그립니다. 아직 재지 않은 기기는 주소 기반의 고정된
  자리(15° 슬롯)에 **점선 테두리의 연한 점**으로 그려서, `"진한 점은 방향 측정됨 · 연한 점은 눌러서 방향 찾기"`로
  구분해 안내합니다. 재기 전에는 방향을 알 수 없다는 사실을 숨기지 않습니다.
- **터치**: 레이더의 점이나 아래 `10m 이내 기기` 목록을 누르면 기존 상세 카드가 열리고, 거기서
  `🧭 방향 찾기`·`🔍 기기 이름 더 읽어오기`를 그대로 쓸 수 있습니다. 스캔 상태는 두 탭이 공유하며
  `내 주변` 탭에도 `▶ 스캔 시작` / `■ 스캔 중지` 버튼과 상태 배지가 있습니다.
- 안내 문구: `내 10m 안 기기 O개`, `신호 세기 기반 대략 거리예요 · 벽/사람에 따라 오차가 있어요`.

## v1.2 (2026-11-19)

- **방향이 엉뚱한 곳을 가리키던 문제 수정**: 레이더의 열 지도 호(arc)가 `Canvas.drawArc` 기준(3시 방향 0°)으로 그려지면서 실제 측정 방향보다 **90° 돌아가게** 표시되던 버그를 고쳤습니다. 또 섹터 인덱스는 왼쪽 경계 기준, 호는 중심 기준으로 계산해 **15°씩 어긋나던** 것도 섹터를 0°/30°/60° 중심으로 통일해 맞췄습니다.
- **측정 진행 표시**: `측정 진행: 8/12 방향`처럼 몇 개 방향을 실제로 쟀는지 보여 줍니다. **4곳 이상** 측정되기 전에는 바늘을 그리지 않고, 그 전까지는 신호 세기 변화만 보여 줍니다.
- **부드러운 피크 보간**: 각 섹터를 양옆 섹터와 0.25/0.5/0.25로 섞어 비교하고, 이웃이 없는 외톨이 섹터는 6dB 깎아 평가합니다. 벽에 반사된 한 점의 강한 값이 바늘을 잡아당기지 못하고, 실제로는 위상차 보간(포물선)과 섹터 내 가중 평균으로 30° 격자보다 세밀하게 방위를 계산합니다.
- **와이파이 팁**: 와이파이일 때만 “한 방향마다 2~3초 멈춰 재면 더 정확해요”를 안내합니다(스캔 주기가 느린 특성).
- **내 폰 연결·등록 기기 표시**: `BluetoothAdapter.bondedDevices`와 `getConnectedDevices(GATT, A2DP, HEADSET)`를 15초마다 확인해 목록·상세에 `🔗 내 폰 연결됨` / `📌 내 등록 기기` 배지를 붙입니다. 권한·예외는 모두 감싸서 블루투스 스택이 튀어도 스캔은 계속됩니다.
- **기기가 내뿜는 이름 강조**: `ScanRecord.deviceName`(방송명)과 `BluetoothDevice.name`(폰이 기억한 이름)을 모두 읽어, 방송명이면 `📢 방송명: 지훈의 AirPods`로, 폰이 기억한 이름이면 `📌 폰에 저장된 이름`으로 구분해 보여 줍니다. 이름이 없으면 기존처럼 `(이름 없음)` + 제조사 표시.
- **`🔍 기기 이름 더 읽어오기` 버튼**: 상세 화면에서만, 사용자가 누를 때만 해당 BLE 기기에 8초 한도로 GATT 연결해 `Generic Access(0x1800) → Device Name(0x2A00)`과 `Device Information(0x180A) → Manufacturer Name(0x2A29)`을 읽습니다. 에어팟·최신 폰·추적기는 연결을 거부하는 경우가 많아 실패하면 “이 기기는 보안상 상세 이름 공개를 막아 뒀어요”라고 솔직하게 안내하고, 성공·실패·시간 초과·취소 어느 경우에도 `disconnect()` + `close()`로 연결을 닫습니다.
- 상세 화면은 AlertDialog 대신 전용 카드(`dialog_detail.xml`)로 바뀌어 방송명·배지·GATT 결과·방향 찾기 버튼이 한 화면에 들어갑니다.

## v1.1 (2026-11-19)

- **목록에 예상 거리 표시**: 각 행의 오른쪽 위에 `약 2.4m`처럼 거리가 크게 나오고, 그 아래에 `-58 dBm`과 세기 막대가 붙습니다. 기지국은 거리를 계산하지 않고 `기지국`으로 표시합니다.
- **거리 계산 정확도**: 기기별 RSSI를 EMA(α=0.28)로 평활화하고, BLE는 광고 패킷의 TxPower(1m 기준 세기)를 우선 사용하며, 와이파이는 2.4/5/6GHz 대역별 1m 기준 세기(-40/-46/-49 dBm)와 실내 경로 손실 지수 2.6을 적용합니다.
- **방향 찾기 모드**: 신호를 눌러 `🧭 방향 찾기`를 열면 Canvas로 그린 레이더 나침반에서 폰을 돌릴 때 방향별 최대 세기를 열 지도(Heat Arc)로 보여 주고, 가장 센 방향을 바늘로 가리킵니다. 피크 방향 ±15° 안에 들어오면 진동과 `🎯 이 방향이 가장 강해요!` 표시가 나옵니다.
- 거리는 어디까지나 신호 세기로 계산한 어림값입니다. 벽·가구·사람에 따라 달라집니다.

## 지금 바로 APK 받기

1. GitHub에서 이 폴더(`android-signal-app`) 상위 저장소로 들어갑니다.
2. `.github/workflows/build-apk.yml` 파일을 추가합니다. (내용은 `GITHUB_WORKFLOW_build-apk.yml` 그대로 복사)
3. **Actions → Build Android APK → Run workflow → Run** 을 누르고, 끝나면 Artifact `signal-detector-debug-apk`를 내려받습니다.

> 저장소에 `main` 브랜치로 푸시가 들어오면 `android-signal-app/**` 경로 변경 시 자동으로도 빌드됩니다.

## 로컬 / Android Studio에서 빌드

```bash
cd android-signal-app
./gradlew :app:assembleDebug            # 전파 감지기        → app/build/outputs/apk/debug/app-debug.apk
./gradlew :app-nearby:assembleDebug     # 전파 감지기 (내 주변) → app-nearby/build/outputs/apk/debug/app-nearby-debug.apk
./gradlew assembleDebug                 # 둘 다
./gradlew testDebugUnitTest             # 두 앱의 테스트(화면 실행·거리 계산·레이더 계산)
```

Android Studio(2023.1 이상)에서는 이 폴더를 그대로 열고 원하는 모듈을 Run 하면 됩니다. (JDK 17, Android SDK 34)

## 앱 사용법

1. 앱을 열고 **권한 허용** (`근처 기기`, `위치`) — 안드로이드가 주변 신호를 앱에 넘겨줄 때 필요한 권한입니다.
2. **▶ 스캔 시작** — 주변 신호가 목록에 쌓입니다.
3. **기준 저장** — 지금 잡힌 블루투스·와이파이 목록을 "평소 상태"로 저장합니다.
4. 이후 처음 잡히는 신호는 목록 맨 위에 `🚨 새 신호` 로, 상단에 빨간 배너로 뜨고 짧게 진동합니다.
5. 항목을 누르면 제조사·주소·처음 잡힌 시각·대략 거리가 나오고, `이 신호는 무시` 로 기준에 넣을 수 있습니다.

## 무엇을 알려주나

| 구분 | 읽는 것 | 알려주는 것 |
|---|---|---|
| 블루투스 | 광고 패킷의 MAC·이름·RSSI·제조사 ID·서비스 UUID | 제조사(Bluetooth SIG 등록명), 기기 추정(에어태그·에어팟·갤럭시·타일·ESP32 등), 대략 거리 |
| 와이파이 | SSID·BSSID·주파수·보안방식·RSSI | BSSID 앞 3바이트(IEEE OUI)로 제조사, 공유기 종류(ipTIME·KT·SKB·LGU+·TP-Link), 2.4/5/6GHz·채널, 보안 방식, 대략 거리 |
| 기지국 | `allCellInfo` 의 LTE/5G NR/3G/2G | 통신사, PCI·셀 ID·밴드, 신호 세기 |

기지국은 이동할 때마다 바뀌므로 **새 신호 알림에서는 제외**했습니다(계속 울리는 것을 막기 위해). 목록에는 표시됩니다.

## 데이터 출처

- `app/src/main/assets/oui.csv` — IEEE MA-L OUI 등록부 (MAC 제조사)
- `app/src/main/assets/ble_companies.csv` — Bluetooth SIG Company Identifiers

## 한계

- 신호의 **방향**은 폰 한 대의 안테나로 저절로 알 수 없습니다. `🧭 방향 찾기`로 한 바퀴 돌려 재야 하며,
  재지 않은 기기는 `내 주변` 레이더에 점선(미측정)으로 표시됩니다.
- 거리는 RSSI 기반 추정값이라 벽·몸 위치에 따라 달라집니다.
- Wi-Fi 스캔은 안드로이드가 2분에 몇 번으로 제한해서, 목록 갱신이 몇 초 늦을 수 있습니다.
- 앱이 화면에 떠 있는 동안만 스캔합니다(백그라운드 상시 감지는 배터리 때문에 넣지 않았습니다).
